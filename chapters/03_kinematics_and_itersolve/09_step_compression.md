# 3.3 步进序列压缩算法（Step Compression）

> 如果没有步进序列压缩，Klipper 的分布式双脑架构就会在物理串口的带宽瓶颈前轰然倒塌。

在上一节，我们通过 `itersolve` 获得了每个电机在未来时间轴上的每一个微步脉冲时间戳。
然而，一个致命的通信工程难题随之而来：

### 带宽悬崖（The Bandwidth Cliff）：
现代高速 3D 打印机的多轴步进频率很容易达到 $200,000\text{ steps/s}$。若一台四轴机床（X, Y, Z, E）总步进率达到 $400,000\text{ steps/s}$：
* 如果上位机简单地将每个脉冲的 32 位（4 字节）绝对时间戳通过串口发送给 MCU，每秒需要的原始数据带宽为：
  $$400,000 \times 4\text{ Bytes} \approx 1.6\text{ MB/s} \approx 12.8\text{ Mbps}$$
* 而常见的工业串口波特率只有 115200 或 250000 bps（最大吞吐量仅 $11.5 \sim 25\text{ KB/s}$），哪怕是 1 Mbps 的 CAN 总线，有效载荷带宽也不过约 $80\sim 100\text{ KB/s}$！

**两者之间存在高达两个数量级（50~100 倍）的带宽鸿沟！**

Klipper 是如何在一个普通串口或 CAN 总线上，支撑起高达数十万甚至上百万步进脉冲的？
答案就是：**步进序列压缩算法（Step Compression）**。

核心代码见：[`klippy/chelper/stepcompress.c`](file:///home/zxf/workspace/code/agy/book/klipper/klippy/chelper/stepcompress.c)。

## 一、 MCU 端的一阶差分执行器模型

步进电机在物理运动中绝不是随机乱跳的，它们绝大部分时间都在平滑地做匀速运动或匀加速运动。

Kevin O'Connor 抓住了这个本质，在 MCU 固件端设计了一个极其轻量级的一阶差分生成器：

$$T_{k+1} = T_k + \text{interval}_k$$
$$\text{interval}_{k+1} = \text{interval}_k + \text{add}$$

基于这个数学模型，上位机向 MCU 发送步进指令时，根本不需要逐一发送脉冲，而是发送一条紧凑的参数包：
```c
queue_step oid=%c interval=%u count=%u add=%i
```

* `oid`：目标步进电机对象 ID。
* `interval`：初始脉冲间隔（单位：MCU 硬件时钟 Tick）。
* `count`：连续发射的脉冲总步数。
* `add`：每个脉冲之后，对下一次脉冲间隔施加的微小增量（16位有符号整型）。

### 物理含义解读：
* **匀速巡航阶段**：`add = 0`。MCU 只需要一次性收到一条仅 5 字节的报文，就能完全自主发射接下来几千个严格等间隔的脉冲！
* **匀加速阶段**：速度 $v(t) = at$，时间间隔 $dt = \frac{1}{v}$。随着速度提升，脉冲间隔逐步减小，`add < 0`。
* **匀减速阶段**：随着速度下降，脉冲间隔逐步拉大，`add > 0`。

## 二、 压缩器在 C 语言中的实现细节

在上位机端，[`klippy/chelper/stepcompress.c`](file:///home/zxf/workspace/code/agy/book/klipper/klippy/chelper/stepcompress.c) 的核心使命是：**寻找一条由 $(interval, count, add)$ 构成的折线，使其对 `itersolve` 算出的真实脉冲时序的逼近误差，绝对不超过预设的最大容差（`max_error`）。**

```text
脉冲时间误差
  ^
  |        +---------------------------------+  <-- +max_error 容差上限
  |       /          ... 压缩逼近折线 ...      \
  |      /                                     \
  |     *   *   *    *   *   *    *   *   *     \ <-- 实际求根脉冲点
  |    /                                         \
  +---+-------------------------------------------+---> 脉冲序号
  |    \                                         /
  |     +---------------------------------------+   <-- -max_error 容差下限
```

### 误差包络拟合过程：
1. 压缩器在环形缓冲区 `queue` 中积累一组脉冲时间戳。
2. 尝试从当前起点开始，用一条参数为 $(interval, add)$ 的二次曲线包裹这些离散点。
3. 只要所有脉冲点的理论时间与差分拟合时间的绝对误差满足：
   $$|T_{\text{approximate}}[k] - T_{\text{actual}}[k]| \le \text{max\_error}$$
   （其中 `max_error` 通常仅为几个时钟周期，等效时间误差小于 100 纳秒，远低于步进电机的机械分辨率），压缩器就会持续将 `count` 向上累加。
4. 一旦下一个脉冲超出容差窗口，立刻封闭当前这批次脉冲，打包为一条 `queue_step` 指令压入发送队列，并开启下一段拟合。

## 三、 惊人的压缩比与性能表现

在实际打印过程中，由于结合了前文介绍的 VLQ（变长整型）编码，一条能触发上百步脉冲的 `queue_step` 指令通常只有 **5 ~ 8 个字节**。

我们可以做一次量化对比：

| 指标 | 未压缩的原始时间戳传输 | Klipper 步进序列压缩 |
| :--- | :--- | :--- |
| **单步占用数据量** | 4 字节 / 步 (32-bit tick) | 约 **0.05 ~ 0.1 字节 / 步** |
| **400k steps/s 吞吐需求** | 1.6 MB/s (12.8 Mbps) | **仅需 20 ~ 40 KB/s** |
| **串口兼容性** | 无法支持，瞬间死机 | 即使是 115200 低速串口也能轻松喂饱 |
| **MCU 中断负载** | MCU 需频繁接收中断解包 | 一次 DMA 接收即可驱动电机运行几十毫秒 |
| **整体数据压缩比** | 1 : 1 (0%) | **高达 95% ~ 99%** |

## 小结

至此，我们已经完整走通了 Klipper 的“运动生成流水线”：
* `G-code` $\rightarrow$ `Move Queue`（速度平方前瞻规划）
* $\rightarrow$ `Kinematics`（机架非线性映射）
* $\rightarrow$ `itersolve`（割线法数值求解出步时间戳）
* $\rightarrow$ `stepcompress`（一阶差分拟合，压缩比 99%）
* $\rightarrow$ 通过微型报文下发给 MCU。

然而，在现代高速打印中，仅仅路径算得准还不够——打印机本体由金属型材、同步带和打印头组成，是一个弹性振动系统。高速急停急起会激发机架的固有共振，在打印件表面形成波纹状的“鬼影（Ghosting / Ringing）”。
